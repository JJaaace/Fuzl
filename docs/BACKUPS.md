## Exact synthetic demo

Start `npm run dev` if needed and open **http://127.0.0.1:5173/?design=backups**. This development-only simulator preloads a confirmed **Synthetic outdoor picnic** and a saved two-option shortlist. It uses the real organizer/guest controls and deterministic fit checks through an in-memory transport. It creates no working real shared link and makes zero API/database/provider requests. Reload resets it. The database scenario is verified separately on disposable PostgreSQL.

1. Choose **Guest plan demo · same link**. Enter **Synthetic Sam**, choose **Going**, check **I reviewed the current plan…**, and choose **Send RSVP**. The original is November 21, 2026, 19:00 New York time at Synthetic park north gate.
2. Return to **Organizer demo → Refresh plan & attendance**. One Going appears separately from votes. Under **One private backup**, choose **Set backup**. In **Backup source**, select **Synthetic indoor games · saved shortlist snapshot**. Manual entry is also available.
3. In **Private backup draft**, enter **Plan date: November 21, 2026**, **Plan local time: 19:00**, **Plan time zone: America/New_York**. The selected option already supplies **Synthetic community room lobby** and its example source link. Leave price blank/unknown. Enter **Backup end time: 20:30** and **Reviewed availability time zone: America/New_York**. In the private condition note, enter **If it rains**. This is a human decision, not a monitored trigger.
4. Choose **Save private backup → Reload backup & fit checks**. It says **Still needs checking**, with the intended two-person scope. Price, hours, route time, room booking and step-free access remain unresolved. Switch to the guest view and reload: only the outdoor plan is visible, with no backup or condition note.
5. Return to organizer. Choose **Switch to backup · preview**. Review the current and proposed plans side by side, the changed-fields summary, public notice and unresolved checks. The condition note is absent from the exact public replacement. Check both **I reviewed the unresolved checks…** and **I approve this exact replacement…**, then **Confirm switch & publish backup**. The existing shared link is retained; the old publication remains in **Published plan history → View published details v1**. The old Going response needs reconfirmation.
6. Choose **Guest plan demo · same link → Reload shared plan / my RSVP**. Read the backup change notice, new meeting point, 19:00–20:30 time and remaining questions. Reaffirm the current plan and choose **Reconfirm RSVP**. Organizer refresh now shows one current Going. It is still RSVP intent, not actual attendance.
7. Try a blocked switch: organizer **Reload backup & fit checks**, enter **99 / USD / total / per-person** for cost, **Save private backup → Reload backup & fit checks → Switch to backup · preview**. A known firm USD 20 budget conflict blocks publication even with approval. Edit the backup or saved constraints and preview again; there is no override button. The previously published plan stays intact.
8. With a valid saved backup preview, choose **Simulate attendee scope changing**. Old fit checks/preview become stale and cannot publish. **Restore reviewed demo scope**, refresh/reload if needed, and create a fresh preview. Unsaved normal-plan and backup edits have replacement guards. A used backup must be edited/saved before switching to it again, preventing repeated accidental publication.

The simulator explicitly switches controlled organizer/guest views. It is not evidence of real Supabase identities, independent browser credentials, hosted database access or mobile rendering.

## Normal saved-session workflow

Reopen an owned saved session with a confirmed published plan. **Set backup** appears under **Choose & publish a plan**. Save the shortlist first if you want to select one of its options. Only this session's **saved** shortlist revision is eligible; an unsaved selection or another session's option cannot be referenced. You may instead author a manual idea.

Enter the activity, meeting point, exact date/local start/zone and an optional useful public link. Cost stays nullable: unknown is not zero; starting price is not a total. Optional same-day end and a reviewed availability zone improve timing checks. Do not guess a zone for saved availability clocks: blank stays unknown. Private condition notes are limited to 500 characters and never copied to the public plan, even after switching. Saving a backup does not edit the plan draft, publish a version, change the shared page or affect RSVPs.

Save working session constraints first. A local summary different from the loaded saved summary or an open fact editor blocks switch preview/publication; the backend checks the latest **saved** summary. Reload backup/fit checks deliberately after other changes. If another tab changed plan metadata, use **Refresh plan & attendance**, then **Reload backup & fit checks**; a stale write preserves entries and does not overwrite the newer record. Reload and source replacement ask before discarding unsaved backup fields. Existing unload, sign-out and account-switch cleanup cover these private fields.

A fresh switch preview always re-evaluates the stored backup against the current nonempty reviewed attendee scope and retained private budgets. It displays exactly what will be public, alongside the current published snapshot, and lists changes to activity, date/time/zone, meeting point, cost and remaining checks. A known firm conflict blocks switching. Resolve it through an actual saved constraint/backup correction, not an approval checkbox. Unresolved evidence is allowed only after explicit acknowledgment and remains on the new public page. Confirmation is a group agreement, not verified fit, booking, ticket purchase or automated weather decision.

If the normal public plan draft has unsaved changes, publishing the backup requires a separate replacement confirmation. Changes typed while a request is in flight remain local rather than being overwritten by its response. A preview is bound to saved evidence and the exact notice; changing either requires another preview. Late previews are rejected after local edits/scope changes, and new previews clear old approval.

## What the fit check can establish

`assessBackup` reuses the existing place assessment, budget, travel and participation checks. The shared evaluator now accepts an explicitly absent resolved area, rather than inventing coordinates or a search radius result. Existing normal Places evaluation keeps its non-null area wrapper and behavior.

A shortlist option is a public **snapshot**, not fresh provider evidence. Fuzl does not parse its time prose, infer coordinates from its address, fetch its link, or treat an old displayed price/hours/event time as newly verified. Backup hours, search boundary/address, travel and booking remain unresolved without applicable evidence. The backup's organizer-declared known total still blocks a known firm budget violation, including retained private limits. Unknown/tentative/unreviewed requirements, free-text accessibility and open questions stay unresolved. Original shortlist warnings and manually entered unresolved lines are preserved.

For timing, a clear backup end can be compared with the complete availability/opt-in window. An unknown end stays visibly unknown; a known out-of-bounds start still fails. For availability facts without a stored zone, the organizer can explicitly supply a reviewed reference zone. Cross-zone or unknown-zone comparisons stay unresolved rather than assuming an offset. Active opt-ins never transfer outside their fixed window, and an opt-in cannot waive a conflicting firm availability fact. Same-day ends are supported; custom overnight durations are not inferred. Invalid/nonexistent/ambiguous local clocks are rejected.

Applicable retained shared-origin route evidence or reviewed current per-person estimates for the **exact destination/date/clock/zone and intended scope** can add a demonstrated firm travel failure. They do not certify a new route, broaden an old shared-origin scope, reveal an origin or carry a duration to another address. Group memory and Balance travel cannot make a failing backup eligible. This feature does not call any route/place/event/weather provider.

The public replacement merges source warnings, authored questions and general unresolved check categories. It does **not** copy raw planning questions, source excerpts, names of people with constraints, private-limit values or owners, individual routes, group memories, private notes or the condition note. Private affordability checks become only a general cost check. The exact preview lets the organizer review any manually authored public text before approval.

## Data and request flow

- One nullable **`backup` JSONB column** on `fuzl_shared_plans`, migration **`202611140006_backups`**. The record stores one stable backup ID, its revision, source option snapshot/origin and saved-shortlist revision, authored public details, optional end/reference zone, private condition note and the version in which it was used. Existing table RLS, direct PUBLIC/anon/authenticated revocations and session/group cascades apply. No new key, environment setting or dependency.
- GET/PUT `/api/private/sessions/:sessionId/backups` reads/checks or replaces that owned plan's backup. POST `/preview` rechecks and returns the exact comparison/proof. POST `/switch` requires the proof, exact public notice, current revisions and **both** publication/unknown acknowledgments. Existing backend Supabase identity, ownership, origin, strict schema/body limits and sanitized error handling cover every route. There is no public backup endpoint.
- `BackupStore` locks the owned session then plan for writes. A switch also pins the scope and existing guest invites while checking private answers, preventing a guest budget or opt-in edit from racing publication. Changes to plan, backup, session revision, constraints, private replies, attendee scope and relevant evidence invalidate the preview. Current check results, rather than only a timestamp, join the private proof. No private values appear in that proof's returned representation.
- Switching and recording the used backup commit in the **same transaction**. The shared `PlanStore.publishSnapshot` method applies the existing lifecycle, publication limit, frozen version, material-change and RSVP rules. It does not replace/reopen links or RSVPs. Stable request IDs/hashes and locks make concurrent duplicates/retries one publication; an altered or superseded retry conflicts. No retry loop or fixture fallback exists.
- Replacement provenance records that the option was an organizer-selected backup (manual or shortlist) and which publication it replaced. The retained ballot ID is the original context, not a claim that the replacement won a new vote. Public guests receive only approved plan details. Earlier version details are now inspectable in organizer history; private backup fields never enter version snapshots.
- Plan details gain an optional same-day **end time**. Existing snapshots without it remain valid and display unknown duration. A known end is visible in the public preview/page, joins the material-change key and must fit a reviewed opt-in window. End-only changes therefore require RSVP reconfirmation. No end is fabricated from a listing. Public unresolved capacity is 48 lines so source/authored/generated warnings can coexist; backup authoring stays bounded to 16 lines, with no silent truncation.

Important code: `packages/planning/src/backups.ts` and `backup-fixtures.ts`; `apps/api/src/backups/`; extracted shared `loadPlaceContext`, `assessPlaces` and `PlanStore.publishSnapshot`; `apps/web/src/backups/`, and the existing organizer/guest plan editors and details.
