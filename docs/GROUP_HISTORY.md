## Real organizer flow

In **Saved groups**, choose a group. **Group history & next ideas** appears before the full ideas editor/session list. It shows the latest three actual outings by default, with **Show all … loaded outings** for the remaining bounded list. The first card is marked **Most recent outing**. Date/local time/zone, actual location, current approved takeaway and an explicit organizer-attendance entry count are compact and wrap on narrow screens. No recap is required to keep a completed outing visible.

**Open outing details** loads the original saved session through the existing owned-session endpoint, replacement confirmation and validation. It targets **Recorded outing & feedback** after asynchronous loading, once, without taking focus away if the user has already started editing another field. Use **Published plan history** for earlier agreements and the existing actual/takeaway controls for corrections or approval/removal. Returning to Saved groups reloads the selected group's recaps. **Refresh past outings** updates them deliberately while staying in the group. There is no polling or promise of immediate cross-device updates.

**Saved ideas · for next time** opens the existing group-scoped Saved ideas list/editor, with no draft reset. Ideas are records of things to consider, not evidence of attendance or a completed outing. A previously visited place may also be intentionally saved to repeat; the app does not infer that all saved ideas are unvisited. Open one of this group's **Saved planning sessions** below, or save a new session into this group, then use **Find places / Events → From your saved ideas → Add idea to candidates → Evaluate saved ideas (no provider call) → review checks → Add to shortlist**. Resolve the area with an existing search first when the normal picker requires it. ## Data, ordering and privacy

This pass adds **no migration, table, key, dependency, account type or browser persistence**. It reuses the actual outing, plan version, approval/feedback-revision and saved idea records. Existing pending hosted migrations are still prerequisites for those features.

The existing authenticated `GET /api/private/groups/:id/outings` enforces verified organizer identity and group ownership. Its query repeats the owner filter in the join, restricts to actual records attached to completed plans, and orders by the **recorded actual local date, clock time and stable ID before LIMIT 100**. It never sorts by the date a record was entered. Zones are shown explicitly; the list is a journal ordered by those recorded local dates/clocks. Cancelled/proposed/status-only completions without an actual record, unused backups and unvisited shortlist/saved-idea candidates cannot enter the result.

Only recap fields are selected/validated: outing/session IDs, actual activity/date/time/zone/meeting point, the **currently active approved takeaway**, its active flag and count of organizer-confirmed attendance entries. SQL returns null for removed/suspended approval, so stale text cannot leak behind a false UI flag. Feedback or attendance/permission changes still suspend approval under the existing rules; the next read removes its recap text. Individual feedback answers/names/notes, source chats, budgets, original snapshots, private notes/proposals, backup condition notes, personal travel records/origins and saved-idea notes are never read into the recap DTO. Earlier public snapshots and private feedback remain in the separate, owned detail workflow.

Attendance counts only the existing explicit organizer-confirmed entries. They are **entries, not verified unique identities**: matching names are not merged, and guest self-reports are reviewed separately in details. Votes, Going RSVPs and intended/opted-in rosters do not establish attendance. Zero means no organizer-confirmed entries recorded here; it does not mean nobody attended. A legacy response missing the optional count is labeled not loaded, never silently zero.

Group changes, account changes, token refresh and aborted/late reads cannot replace the current group's cards with earlier results. Loading, empty and failed reads have different states. Re-entering the group remounts only the read-only recap list, refreshing approval/actual changes while preserving the Saved ideas editor. Group/session replacement continues to use existing unsaved-work guards. No new guest history/recap endpoint exists. The existing account-free single-plan actual/feedback workflow is unchanged; group takeaways and this history collection remain organizer-only.

Important code: `OutingStore.past` and `pastOutingsSchema`; `apps/web/src/outings/PastOutings.tsx` and `GroupHistory.tsx`; the existing `SavedGroups`/session-open/outing-editor path; `group-history-fixtures.ts`, `HistoryDemo.tsx` and its explicit in-memory transport.
