# Section 4 — screenshots and reviewed transcripts

Implemented November 6, 2026. Section 4 is authorized by Jace's attached request, which advances the original specification's boundary. Stop before Section 5. Changes remain local; no push, deployment, accounts, storage service, or database.

## Try it

Start `npm run dev` and open http://127.0.0.1:5173. Keep `AI_PROVIDER=gemini`, `GEMINI_API_KEY` and `AI_ENABLED=true` privately in `apps/api/.env`; no new credentials or model setting is needed. OpenAI remains separately selectable for pasted-text planning. Screenshot reading currently requires Gemini and never switches the configured provider automatically.

1. Select multiple PNG/JPEG images. Use the committed **synthetic** images in `fixtures/screenshots` for development. No image-reading request happens during selection, preview, ordering, removal, or clearing. Public provider-configuration GETs contain no images.
2. Check visible positions and thumbnails. Move earlier/later with real keyboard-accessible buttons, remove individual files, or clear all. File names stay in the browser; requests use random stable references.
3. Read the disclosure and click **Read screenshots** once. This is one AI request through Fuzl's backend to Gemini, using images in the displayed order. Loading disables duplicate submission; Cancel stops waiting and asks the backend to abort. Google may already have processed a cancelled request.
4. Review message text, alias, visible date/time and uncertainty, with their screenshot references. Blank alias means Unknown; bubble color/position is not identity. Original readings remain inspectable separately from organizer edits. Correct missing text or add a message manually after selecting its source screenshot. Overlaps stay separate, with optional uncertain-duplicate notes; removing a reviewed message does not erase its original reading until Clear.
5. Click **Use reviewed transcript as draft**. Replacing a nonempty different draft requires confirmation. The accepted summary stays and shows its normal source-mismatch warning. This step does not call AI. After linking, transcript edits update that draft. Invalid aliases or blank messages block analysis until corrected. Manually editing the main textarea detaches screenshot traceability; use the reviewed transcript again to restore it.
6. Click **Analyze conversation** separately. It is a second AI request, using the existing text extraction contract and optional conversation reference date. Upload time is never used as the conversation date. Review the candidate warnings, choose **Use extracted summary**, and confirm replacement of any existing summary including unapplied edits. AI claims stay unreviewed and no model-reported confirmation is accepted automatically.
7. Expand a fact's supporting text. Its quote leads to matching reviewed transcript messages, original image-model readings versus organizer corrections, and screenshot references. Multiple matching occurrences are all shown. An exact quote match proves correspondence to the submitted transcript, not that the model read the pixels correctly. Apply a fact edit to mark that planning claim reviewed; this does not certify visual transcription.

Pasting text, samples and blank manual summaries still work independently of screenshots.

## Limits and validation

Both browser and backend enforce up to **5 files**, **5 MiB each**, **15 MiB total**, **4096 pixels per side**, **8,000,000 pixels per image**, and **20,000,000 pixels per batch**. Only static PNG and JPEG are supported. HEIC, GIF, WebP, SVG and other formats need exporting first. Browser headers/dimensions are checked before browser pixel decoding; the server independently detects actual format, checks dimensions/pages, and fully decodes pixel data with Sharp 0.35.5. Filenames and client MIME types are not trusted. Truncated/corrupt/unsupported images are rejected with controlled errors.

Uploads are bounded JSON containing base64 bytes, not filesystem paths. Express caps the encoded upload at 21 MiB, disables compressed request bodies, and admits only one image upload at a time. Google's inline-request budget is 20 MB including encoding/prompt/schema overhead; sets near the 15 MiB binary maximum may need further reduction. The browser reserves overhead and rejects oversized encoded requests before sending; the backend independently caps the actual provider body before a provider call. No Files API or remote URL fetching is used.

Both analysis routes share one active operation, three attempts/minute and ten attempts/process, plus a 45-second backend deadline. Configuration/schema rejection happens before the attempt counter; malformed image content discovered after admission can consume a local attempt without a provider call. Reading and planning are separate attempts. There are no automatic provider retries, paid fallbacks, model switches or billing changes. Quota/account failures ask the organizer to inspect the project before another deliberate attempt.

The structured transcription contract checks shape, unique message IDs, screenshot reference coverage/order, message screenshot order, earlier duplicate references and explicit uncertainty for unknown attribution. It cannot independently establish visual truth. Missing/cropped text is not reconstructed, relative dates remain ambiguous, readable corrections/conflicts are retained, and organizer aliases remain aliases. Unknown attribution becomes an explicit Unknown line with no participant identity. A reviewed alias becomes an explicit source prefix, so the unchanged planning speaker/source validator can check it without bypasses or invented names.

## Important state changes

- Screenshot files/order have a revision. Each read captures that exact revision and ordered references. Editing the selection or existing transcript during reading causes the late result to be discarded. Reordering away and back still invalidates it.
- A read result opens transcript review only if it is current. Rereading an existing transcript requires replacement confirmation; failure keeps it. It never replaces a conversation or summary by itself.
- Transcript originals are immutable snapshots. Current messages retain their source ID; changes show Organizer corrected or Organizer entered manually. The text sent for planning includes explicit visible-time/uncertainty annotations, without date inference.
- After using a transcript, linked edits update the draft and source revision. Planning results from an older draft/transcript revision cannot be accepted, even when text happens to match again. The reference-date/provider checks remain. Changing accepted fact edits still requires the existing summary replacement confirmation.
- Summary acceptance captures its transcript snapshot. Later transcript edits cannot silently change that summary's evidence. Removing an image revokes its preview; reference/text evidence remains and says image unavailable. **Clear screenshots and transcript** clears files, current/original transcript and screenshot trails; the existing conversation draft and accepted summary/source quotes deliberately stay, as the confirmation explains. Clear draft / Remove summary are their separate existing actions. Reload clears all app state.

## Temporary-data lifecycle and privacy

Files, object URLs, transcript and source snapshots live only in browser memory. Removed/replaced images and component cleanup revoke object URLs. A failed or abandoned local selection releases any newly created previews. Clearing during selection or reading advances the revision and aborts waiting, so late work cannot repopulate the cleared state. Original image-model readings remain only until replacement, explicit Clear, or reload.

The API parses bounded uploads and validates images in memory. Sharp receives Buffers, not file paths; its operation cache is disabled. No temporary upload directory, disk upload, repository write, database, browser storage, provider File API, or persistent image cache exists. The route releases request-body references in finally; validated image buffers are zeroed and released on success/failure/cancellation. An already-running native decoder/network operation may finish before its references can be released, and JavaScript base64/body strings are garbage-collected; this is not a claim of instantaneous secure memory erasure. Routine tests exercise decode/release helpers and cancellation/failure guards, not a forensic memory-deletion guarantee.

Keys remain backend-only, in headers to a fixed host. No request URLs contain them. Raw images, conversations, transcripts, provider bodies, and arbitrary errors are not logged. Section 3's distinct sanitized diagnostics and matching UI error references remain. Provider data handling is separate: Google's unpaid-service terms allow product improvement and human processing, with regional differences. Use synthetic content only during this development stage. Clearing Fuzl does not delete provider-held content or change Google's policy. Review [Google terms](https://ai.google.dev/gemini-api/terms#unpaid-services) and [project setup](GEMINI_SETUP.md).

## Provider choice and request format

Rechecked official Google model, pricing, structured-output, image-understanding, and GenerateContent documentation on November 6, 2026. **gemini-3.5-flash-lite** supports image input and structured text output, with a documented Free Tier. No vision-model switch, paid model, new Google SDK, or billing enablement was necessary. Actual key/project tier and available quota are not inspected by Fuzl.

`transcribe.ts` uses the same small Gemini transport as text extraction: native REST `v1beta/models/gemini-3.5-flash-lite:generateContent`, `x-goog-api-key`, system instructions, ordered reference/text + inlineData parts, and application/json responseJsonSchema. Conversation/image content and schema-owned source labels are untrusted data. Source references in the schema are literal enums, never instructions. App validation still runs independently after response parsing.

Official sources: [model](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite), [pricing](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.5-flash-lite), [image input and inline limits](https://ai.google.dev/gemini-api/docs/image-understanding), [GenerateContent](https://ai.google.dev/api/generate-content), [structured output](https://ai.google.dev/gemini-api/docs/structured-output), [Sharp security](https://sharp.pixelplumbing.com/security/).
