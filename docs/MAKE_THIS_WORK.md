## Normal saved-session flow

Reopen an owned saved session, apply/cancel open fact editors, and run the existing Places or Events search. **Make this work** appears beside the discovery shortlist’s no-fit message, using that returned candidate page, not a newly fetched list or an independently edited published ballot. Existing resolved-area, ZIP, radius, provenance, source-correction and memory behavior remains in place.

The action evaluates existing evidence, gives at most three distinct previews and never changes a fact automatically. Each preview shows original/suggested values, the affected options, derived counts and unresolved checks. Explicit approval applies a single change to the current **working summary**. The summary displays an organizer decision with old/new values, original source references, time and the relevant newly recorded check sources. Saving remains explicit and uses the existing session revision/ownership checks. Publishing a changed plan and reconfirming RSVPs remains the separate 8B workflow.

Use **Recheck current places (no provider call)** or the new **Recheck current events (no provider call)** after applying while the current search context remains valid. These reuse the cached original list and current working facts. Saving or changing private/memory context can invalidate that search; an expired/replaced cache requires a fresh deliberate search. No automatic search, fallback, retry or provider call is added. Existing source text, review labels, guest-answer provenance, unknown values, plan snapshots and RSVP intent are preserved.

## Supported bounds and evidence

- **Time:** one confirmed, reviewed, explicitly flexible **group outing window**, matching the Places search window or the current group window for Events. Try whole-minute shifts from −60 to +60 minutes while preserving duration, date and reliable area time zone. No overnight date rollover or daylight-saving ambiguity is invented. Exactly one applicable flexible window is required; ambiguity needs clarification. Event start/end are fixed provider facts; only the group’s desired window changes.
- **Travel:** one confirmed, explicitly flexible group limit with a known mode, comparison and duration. Try +1 through +10 whole minutes. Every other firm/flexible travel bound remains active. A sourced estimate must match the exact destination, date, arrival time, time zone and mode, and an organizer explicitly confirms a shared departure point used by everyone’s relevant journey. Different addresses/modes/arrival times or radius-only data remain unresolved. Strict “under” stays strict. These organizer-recorded estimates are not live traffic measurements or guaranteed durations. No route-provider integration is added.
- **Firm requirements:** every supplied confirmed availability must contain the proposed full window; a shift outside even one is rejected. Complete confirmed availability covering the intended participants (or a confirmed whole-group window) is required for the preview’s full-fit label. Unknown/unreviewed availability remains an explicit check. Current budgets, radius, location/address, duration, event status and accessibility/other firm facts still use the existing evaluators. Unsupported free-text accessibility or similar requirements are not inferred. The system never relaxes a firm fact or changes a guest’s answer.
- **Remaining checks:** unknown total cost, dated hours, duration, address, applicable travel evidence or relevant access/tickets are not invented. The preview uses **Still needs checking** when these remain. A dated organizer-recorded group-access source can report tickets/booking not required, available, or unavailable for an exact window/address. “Available” is not a reservation. Source check dates/links remain visible and source claims can become stale. The ordinary cards’ “fits checked constraints” label remains distinct from a reservation; the adjustment preview also requires clear availability and applicable access evidence for its stronger fit count.
- **Ranking:** current constraint eligibility runs before preferences, including approved group memory. The helper does not create a replacement ranking system or global-optimality score. It prefers the smallest single supported change yielding a known fit, then useful changes that remove a known blocker but still need checks. Equivalent affected-option/outcome previews are deduplicated. Counts come from the exact bounded list evaluated; no claim covers unreturned venues/events.

## Privacy, state and request flow

Private feasibility stays server-side. If the session retains **any private spending answer**, the adjustment endpoint withholds **all suggestions, option counts, option metadata and candidate-specific explanations**, independent of that person’s value or identity. This deliberately prevents repeated time/travel comparisons from becoming a threshold oracle. It does not weaken the normal private feasibility checks or reveal the private values/owners. This conservative limitation can make the helper unavailable for otherwise valid real sessions.

Owner routes are POST `/api/private/sessions/:sessionId/adjustments/preview` and `/apply`, behind existing Supabase verification and session/group ownership. Search responses include an opaque `workId`. The server retains only the public candidate list, query, owner/session IDs, revision and one-way planning/context fingerprints in bounded in-memory caches; it does not cache raw chats or private limits for the helper. Fifty search and fifty preview entries expire after ten minutes. A new search/recheck for the same account/session/input type replaces its earlier snapshot. Restart loses previews. Limits: one helper request in flight per organizer, ten deliberate preview/apply requests per minute, at most 23 candidates, 130 single-change trials and three manual evidence records/previews. No automatic retry loop.

Preview/application pin the exact summary, evidence, candidate generation, current saved revision and server-private/memory context. Object key order is normalized for hashing without dropping values or weakening schema/source validation. Application rechecks context and returns only the adjusted working summary/query and a bounded organizer decision; it does **not** write the database or update a plan. Repeated identical application returns the same decision ID/time. Explicit Save session uses the existing optimistic revision and immutable-quote checks. Changes after a response but before a later save are still caught by that save’s revision check.

Client edit counters, abort/sequence guards, fingerprints and open-editor checks prevent late responses or edit-and-undo from replacing newer work. Review/approval controls do not count as new planning edits and thus do not invalidate their own preview; source drafts have their own edit tracking and unsaved-work markers. Unrecorded checks must be recorded or cleared before preview/application, and replacement confirms discarding them. Source URLs reject malformed URLs, credentials and key/token query/fragment fields without printing input or throwing into the UI. Detailed raw DB/auth exceptions and raw conversations are not logged.

Organizer decisions are optional additions to the existing saved JSON summary, bounded at 20/session. They preserve the original fact’s supporting quote references and relevant organizer-recorded proof, with no new SQL table/migration. Retained checks only support later evaluation when destination/date/window/mode still match; provider requests and public ballot/plan pages never receive this decision metadata or shared-origin fields. These are organizer-authored records, not cryptographic audit or independently verified routing/booking facts.

Important code: `packages/planning/src/adjustments.ts` (bounded evaluator/application), `visit-evidence.ts` (sourced checks), `organizer-decisions.ts` (saved record); `apps/api/src/adjustments/` (owner-bound expiring caches and routes); `apps/web/src/adjustments/` (preview/editor/demo); existing Places/Events evaluators and cards (unchanged hard-check order, sourced annotations); App/SaveSession (working-only application and explicit persistence).
